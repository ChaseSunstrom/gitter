## lens: adversary
- HIGH — `src/api/collab.rs:210,580-592,601` — History is capped by op count (1000), not size. One op can be `[-N, "<1M chars>"]` and still pass the 1M-character text check. History can reach about 2 GB per session, and each broadcast copy adds more. A stale `revision` makes `change` run up to 1000 large transforms while holding a std mutex on an async worker. Reproducer: as any writer on your own repo, join, then POST `/ops` about 900 times a minute with `{"revision":0,"op":[-1048576,"<1048576 chars>"]}` (the 900/min budget at `collab.rs:565`, plus an op that deletes the whole text and inserts 1M characters). Fix: evict history while the total units exceed about 4M, cap one op's inserted units, and cap the broadcast size. — high
- MEDIUM — `src/api/collab.rs:671-693` — `events` checks `Repo::writable` only on connect. A removed collaborator, suspended user or revoked token keeps getting every keystroke and cursor for as long as the stream lives. Reproducer: bob opens the stream, alice removes him as a collaborator, alice types, and bob still receives the `op` events. Fix: re-check access on a timer (for example each keep-alive tick) and end the stream when it fails. — high
- MEDIUM — `src/api/collab.rs:208,484-537,519` — `MAX_SESSIONS` is global, and `join` accepts any valid path, even a nonexistent file, for any writer. The sessions linger for an hour. Reproducer: loop `POST /api/repos/me/mine/collab {"branch":"main","path":"f<i>"}` 200 times, and every repo on the server gets 409 "Too many files". Fix: cap sessions per user and per repo, and require the file to exist or the repo to be empty. — high
- MEDIUM — `src/api/collab.rs:431,464` → `static/js/pages/editor.js:132` — The `Co-authored-by` trailer is built from `display_name`, which is only length-limited (`account.rs:312`) and so can hold newlines, `<` and `>`. The client pastes it into the committer's message. Reproducer: set display_name to `Eve\nSigned-off-by: Vic <v@x.io>`, type in a shared session, and the committer's commit contains the injected line. Fix: build the trailer from sanitized text (drop control characters and `<>`, fall back to the username). — high
- LOW — `src/api/collab.rs:277-279,266,307` — Counts are not bounded, and `base_len` and `Build` add in `usize`, which wraps in release builds. `[9223372036854775807,-9223372036854775807,8]` on a 6-unit text passes the length check and then panics on the slice in `apply` (the panic poisons the session mutex). Fix: reject any count above `MAX_TEXT` in `parse`. — high
- LOW — `src/api/collab.rs:611` and `src/api/mod.rs:469` — `presence` is exempt from the write limiter and has no budget of its own, unlike `change`. Each call broadcasts to up to 20 streams, and enough of them make the others lag and force a resync. Fix: apply the `collab:` limiter in `presence`. — high
- LOW — `src/api/collab.rs:570` and `static/js/collab.js:98` — `client` is a free string that every peer sees. Posting an op with the victim's `client` makes the victim treat it as its own acknowledgement and skip applying it, so the victim's text silently diverges. Fix: key the acknowledgement by a server-issued id or by user plus client. — medium
- LOW — `src/api/collab.rs:457-469,611-625` — `enter` runs from `join` and `presence` with no stream. A person added that way (a late presence POST, or an unopened stream) never leaves, because only `Watching::drop` removes people. It stays as a ghost avatar and takes one of the 20 slots. Fix: only `events` adds people, and `presence` ignores non-members. — medium

## lens: edge
- MEDIUM — `static/js/pages/editor.js:216` and `src/api/collab.rs:529,491-495` — The commit uses `session.base`, which is fixed when the session is created and only moves via `committed`. Any other push to the branch, even to another file, makes every commit from the session fail with 409. Reloading rejoins the same session with the same stale base. Reproducer: alice and bob are in a session, carol pushes to main, alice commits and gets "Someone else changed this branch", and reloading doesn't help. The session isn't dropped until it has been idle for an hour with nobody connected. Fix: drop a session when its last person leaves, or refresh `base` to the head when the file's blob is unchanged. — high
- MEDIUM — `src/api/collab.rs:484-537` — The lookup and the insert are not atomic, and `git.resolve`, `ls-tree` and `blob` are awaited in between. Two people opening the invite link together get two separate sessions for one file. Reproducer: `tokio::join!(join(alice), join(bob))` on a fresh file gives different ids. Fix: re-check for a match under the `SESSIONS` lock before inserting. — high
- MEDIUM — `src/api/collab.rs:653-660` — `Watching::drop` deletes the `Person` entry on the last stream close, which discards `typed`. A typist who closes the tab or reconnects (for example after the `Lagged` handling at `:689`) is no longer credited. Reproducer: nina types, closes her tab, alice commits, and `co_authors` is empty. The README says everyone who typed is credited. Fix: keep a separate `typed: HashMap<i64, String>` that outlives presence. — high
- MEDIUM — `static/js/ot.js:64-72` — `diff` splits UTF-16 surrogate pairs. Inserting 😁 before 😀 produces `[1,"\uDE01\uD83D",1]`. `JSON.stringify` writes the lone surrogates as escapes, serde_json rejects them, `sendOp` fails, `resync` runs, and the typed emoji disappears. Deleting the first of two adjacent emoji gives `[1,-2,1]`, which a concurrent insert between them turns into a lone-surrogate document. `scripts/ot-check.mjs` never serializes, so it misses this. Fix: after computing `p` and `q`, step `p` back if `old[p-1]` is a high surrogate and step `q` back if `old[old.length-q]` is a low surrogate. — high
- MEDIUM — `static/js/collab.js:110` — Signature names use `display_name`, so `c.includes(': ${ev.user} <')` is false for any user with a display name. Every remote op from such a user triggers a `GET` of the full state (up to 2 MB), once per other participant. Fix: remember the `ev.user` values already fetched in a Set. — high
- LOW — `static/js/collab.js:42` — `reset` replaces the textarea with the session text. Typing locally and then clicking "Edit together" silently discards that typing. Fix: after joining, send `diff(st.text, ta.value)` as the first op. — high
- LOW — `static/js/collab.js:123-125` — The editor stays read-only until the first `init`. If the stream gets an HTTP error (a 429 from the per-IP limiter, for example), `EventSource` stops retrying and the editor is frozen with no message. Fix: add an `es.onerror` that toasts. — medium
- LOW — `src/api/collab.rs:325` — `ls-tree` without `-z` still quotes `"` and `\` in filenames, even with `core.quotePath=false`. Such an existing file isn't matched, the session starts with empty text, and the commit overwrites the file. `git.rs:404` has the same flaw. Fix: use `-z` and split on NUL. — medium

## Acceptance criteria
- Live shared text, cursors, presence and commit with co-authors: met for the happy path (`tests/collab.rs` and the `ui-check` step cover it). The gaps are the leaver and reconnect case above.
- "The branch moved, so refuse": met, but it can't be recovered from (stale base).

## Implicit decisions
- Sessions live only in memory, keyed by (repo, branch, path).
- The client composes the commit trailers.
- Cursor positions are UTF-16 offsets.
- 1M characters, 20 people, 200 sessions and a 1000-op history.
- The `collab:` budget is 900 requests per 60 seconds.
